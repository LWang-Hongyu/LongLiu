# 病根诊断与修复计划

## 背景

审稿视角第二轮迭代：P0-P5 已全部完成，但发现两个致命症状共享同一个病根。

## 症状

### 症状 1：P3 Trace 灾难性违约率 LongLiu 15.0% > CRUX 4.2%
- Synthetic 上 LongLiu 灾难性违约 ~15%，CRUX ~4.2%
- 审稿人看到两张表对比会质疑 "protective scheduler" claim

### 症状 2：轻负载（64 hosts）被 CRUX 反超
- 64 hosts/96 jobs：CRUX 86.7% vs LongLiu 84.2%
- 竞争强度 < 0.5 时带宽充裕，无事可调

## 病根

### 病根 1：累积 urgency 无遗忘机制 → 长尾崩溃
- `U_i = A^cum / E^cum` 是全历史累积量
- 早期建立领先的 job 即使后来挨饿，U 也爬得极慢
- 旧账还不完 → job 长期困在 P0/P1 → 吸收态
- Synthetic 上所有 job 同时起步，旧账效应被对冲
- Trace 上 job 到达分散，先到者的"信用"压制后来者整个生命周期

### 病根 2：动态机制"永远在线" → 轻负载被 CRUX 反超
- 竞争强度 < 0.5 时无事可调
- LongLiu 每个 epoch 仍在做两件多余的事：
  1. 噪声级优先级抖动：所有 job π 在 0 附近，仍在 P0-P4 间按噪声分档
  2. 启动保护 churn：几乎每个时刻都有 job 处于首轮 P6 保护期

## 修复方案：控制论四件套

| 机制 | 控制论对应 | 修复症状 | 实现量 |
|------|-----------|---------|:------:|
| 死区：\|π\|<δ 时强制映射 P3 | actuator dead zone | 轻负载噪声抖动 | ~3 行 |
| 滑窗 urgency：U_i 只在最近 W 个 epoch 上计算 | forgetting/anti-windup | 累积惯性 | ~10 行 |
| 优先级老化：连续 L 个 epoch 带宽份额<θ 则强制升一级 | starvation freedom | 灾难性违约有可证上界 | ~10 行 |
| 迟滞：跨档需越过阈值 ±h | anti-chattering | 振荡，两个症状都受益 | ~5 行 |

## 补丁

### 补丁 1：启动保护改为"收敛即退"
- 退出条件：EMA 相对变化 < 5% 或最多 3 个 epoch
- 启动优先级从 P6 降为 P5

### 补丁 2：DWRR 地板（可选）
- P0/P1 各 5% 最小 DWRR 权重
- 工作守恒：空闲时零代价，拥塞时给尾部兜底

## §64-host 10 seeds 诊断结果

| 策略 | Overall% | Mean SAS | p_vs_CRUX | Jain Index | Catastrophic |
|------|:-------:|:--------:|:---------:|:---------:|:-----------:|
| Fair | 74.2% | 2.236 | 0.771 | 0.552 | 0.83% |
| SRPT | 80.0% | 2.233 | 0.529 | 0.546 | 0.83% |
| CRUX | 87.1% | 2.240 | N/A | 0.562 | 0.83% |
| LongLiu | **88.3%** | 2.213 | 0.256 | **0.568** | 0.83% |

### 结论

1. **LongLiu Overall 88.3% > CRUX 87.1%** → 之前 5 seeds 看到的 "CRUX 反超" 是噪声
2. **p=0.256 > 0.05** → 差异不统计显著，低竞争下所有策略收敛
3. LongLiu Mean SAS (2.213) 略低于 CRUX (2.240) → 优先级抖动在低竞争中仍有微小负效应
4. 灾难性违约率完全一致 (0.83%) → 低竞争下不成问题
5. **病根 2 优先级下降**：启动 churn 在 10 seeds 下不导致显著反超

### 优先调整

1. **主攻病根 1**：启用滑窗urgency (window_size=8) + 老化 (aging_L=5)，预期改善灾难性违约率
2. 死区 (dead_zone=0.1) 和迟滞 (hysteresis=0.05) 作为辅助，进一步缩小 SAS 差距
3. 启动保护补丁仍然实施但不紧急

1. ✅ 先测再改：64-host 补 seeds + 启动期占比插桩
2. ✅ 实现滑窗 urgency + 死区 + 老化 + 迟滞（详见下方 §Implementation）

## §Implementation：控制论四件套代码实现

### 文件修改

| 文件 | 修改内容 |
|------|----------|
| `longliu_sim/policy/longliu.py` | 新增 5 个参数、3 个运行时状态、3 个插桩计数器 |
| `longliu_sim/job/job.py` | 新增 `deque(maxlen=W)` 滑窗、`sliding_avg_iter_ms` 属性 |

### 死区（LongLiu.get_dscp, ~3 行）

```python
if self.dead_zone_delta > 0 and abs(pi) < self.dead_zone_delta:
    return 26  # P3（静默）
```

- 默认 `dead_zone_delta=0.1`
- 轻负载竞争 < 0.5 时所有 job 的 pi ≈ 0，死区强制保持 P3 不变
- 只有 pi 真正偏离时（有 job 落后 SLO）才会触发优先级变化
- 修复病根 2："没事别动"

### 滑窗 Urgency（Job 类 + LongLiu.allocate, ~10 行）

```python
# Job.__init__
self._iter_times_deque: deque = deque(maxlen=8)  # W=8

# Job.on_comm_end
self._iter_times_deque.append(iter_ms)

# LongLiu.allocate —— 替代全历史平均
avg_iter_ms = job.sliding_avg_iter_ms  # 最近 W 次平均
```

- 修复病根 1："遗忘旧账"
- 早期建立的领先优势只在滑窗内有效，连续挨饿 W 次后旧账清零
- 与 `accumulated_iter_ms` 并存，向后兼容

### 迟滞（LongLiu.allocate, ~15 行）

```python
# 每 epoch 最多移动 1 个优先级档位（DSCP level）
if level_diff > 1:
    dscp = dscp_levels[old_idx + 1]  # 只升一档
elif level_diff < -1:
    dscp = dscp_levels[old_idx - 1]  # 只降一档
```

- 修复两个病根共同问题：优先级在 0 附近来回振荡 → 分配抖动
- 使 DSCP 变化轨迹变得平滑可预测

### 老化（LongLiu.allocate, ~10 行 + 5 行后处理）

```python
# 分配前：检查上次饿死计数
starved = self._starved_epochs.get(jid, 0)
if starved > 0 and starved % self.aging_L == 0:
    dscp = dscp_levels[curr_idx - 1]  # 强制升一级

# 分配后：更新饿死计数
if was_allocated:
    self._starved_epochs[jid] = 0
else:
    self._starved_epochs[jid] = prev + 1
```

- 修复病根 1：长尾崩溃"有可证上界"
- Liveness 保证：任一 job 最多饿死 L×6 个 epoch 后必然到达 P5
- 默认 `aging_L=5`，`aging_theta=0.05`

### 启动保护补丁（待实现）

EMA 相对变化 < 5% 或最多 3 个 epoch 退出启动期。

## §v2 10 seeds 最终结果

### 修正后（基线未受污染）

| 策略 | Overall% | Mean SAS | Catastrophic | p_vs_CRUX |
|------|:-------:|:--------:|:-----------:|:---------:|
| Fair | 24.6% | 0.771 | 1.7% | 3.0e-4 |
| SRPT | 27.5% | 0.824 | 10.8% | 0.257 |
| CRUX | 29.2% | 0.809 | 10.0% | N/A |
| **LongLiu** | **39.2%** | **0.837** | 27.5% | 0.333 |
| LongLiu_v2 | 34.6% | 0.798 | **26.3%** | 0.444 |

### 关键发现

**控制论四件套在高竞争（16 hosts, 24 jobs）下有害：**
1. **Overall -4.6pp**：34.6% < 39.2%
2. **Mean SAS -0.04**：0.798 < 0.837
3. **Catastrophic 基本持平**：26.3% ≈ 27.5%
4. **p 值更大**：0.444 > 0.333（更不显著）

### 原因分析

| 机制 | 预期效果 | 实际效果 |
|------|---------|---------|
| 死区 (0.1) | 消除抖动 | 抹平优先级梯度，P1/P0 job 被误分到 P3 |
| 滑窗 (W=8) | 遗忘旧账 | 8 次太短，引入更多噪声 |
| 迟滞 (h) | 防振荡 | 阻碍高竞争下需要的快速优先级调整 |
| 老化 (L=5) | 兜底 | 让低优先级 job 涌入 P6，加剧竞争 |
